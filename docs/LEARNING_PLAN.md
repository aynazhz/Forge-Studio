# ⁧برنامهٔ یادگیری Forge Studio⁩

⁧هدف این برنامه آن است که دانشجو از مرحلهٔ بعد مسئول نوشتن تغییرها باشد و بتواند مسیر داده، خطا و آزمون را در دفاع توضیح دهد. برای هر نوبت ابتدا یک مسئله را انتخاب کنید، نمونهٔ کوچک را تمرین کنید، تغییر را خودتان بنویسید و بعد diff و نتیجهٔ آزمون را برای بازبینی بدهید.⁩

1. ⁧**راه‌اندازی**. با پوشهٔ پروژه، Git، `package.json` و lockfile آشنا شوید. `npm ci` و `npm run dev` را اجرا کنید. نام فایل مجازی و نام فایل روی دیسک را از روی UI و سورس تشخیص دهید.⁩
2. ⁧**React و TypeScript**. مقدار primitive، آرایه، `Record`، union، JSX، props و `useState` را تمرین کنید. ابتدا یک شمارندهٔ مستقل بسازید، سپس در نمونه مقدار و متن را تغییر دهید. قبولی وقتی است که تفاوت state شمارندهٔ داخل Preview با state فایل‌ها را توضیح دهید. [درس ۱](lessons/01-browser-runtime.md)⁩
3. ⁧**ادغام ویرایشگر و اجرا**. `useRef`، `useEffect`، subscribe/cleanup و iframe را مرور کنید. یک import را اصلاح و سپس عمداً خراب کنید. مسیر خطا را از Sandpack تا رابط دنبال کنید و آزمون مرورگر را اجرا کنید. [شواهد مرحلهٔ ۱](evidence/STAGE_1.md)⁩
4. ⁧**درخت و تب‌ها**. عملیات خالص و شناسهٔ پایدار را با سه ورودی روی کاغذ تمرین کنید. یک فایل داخل پوشه بسازید، آن را باز کنید، منتقل کنید و علت سالم ماندن تب و تغییر مسیر import را توضیح دهید. برای یکی از سناریوها assertion بنویسید. [درس ۲](lessons/02-ide-core.md)⁩
5. ⁧**ذخیره و آزمون**. درخواست و تراکنش IndexedDB، Promise و نقش نسخهٔ رکورد را تمرین کنید. یک پروژه را بعد از `Saved locally` دوباره باز کنید. اجرای دو تب تست stale revision و محل نمایش خطای ذخیره را دنبال کنید. [شواهد مرحلهٔ ۲](evidence/STAGE_2.md)⁩

## ⁧شیوهٔ همکاری با ChatGPT⁩

⁧در آغاز هر گفت‌وگو مسیر مرحله، آخرین diff و نتیجهٔ اجرای واقعی را بدهید. ابتدا راهنمایی برای فهم مفهوم و مسیر فایل‌ها بخواهید. بعد یک راه‌حل کوچک خودتان بنویسید. ChatGPT رفتار نسخه، لبه‌های خطا و آزمون را بازبینی کند. پس از اصلاح، دانشجو آزمون را اجرا و نتیجه را در `docs/PROGRESS.md` ثبت کند. در پایان جلسه بتوانید بدون نگاه‌کردن به پاسخ ابزار، ورودی تابع، وضعیت قبل و بعد و راه بازتولید خطا را توضیح دهید.⁩

## ⁧گام نخست مرحلهٔ ۳⁩

⁧1. در `src/features/workspace/PreviewPane.tsx` از فراخوانی `new SandpackRuntime` شروع کنید. سپس `sandboxSetup` در `src/features/runtime/sandpack.ts` و آزمون `tests/browser/runtime.spec.ts` را بخوانید. از روی کد مشخص کنید adapter چه داده‌ای را دریافت می‌کند و Preview چه وضعیت‌هایی را نشان می‌دهد.⁩

⁧2. یک شاخهٔ آزمایشی برای تصمیم runtime بسازید. پیش از تغییر Workspace، یک پروژهٔ React/Vite کوچک را روی runtime کاندید اجرا کنید و شروع، نمایش خطا، دریافت خروجی و توقف را در Chromium اندازه بگیرید. دسترسی شبکه، نیازمندی‌های cross-origin isolation و مجوز نسخهٔ مورد بررسی را از منابع رسمی ثبت کنید.⁩

⁧3. جدول تصمیم و یک سناریوی قابل تکرار را برای بازبینی ارائه کنید. پس از مقایسه و انتخاب، کار مرحلهٔ ۳ با افزودن کوچک‌ترین اتصال لازم در adapter آغاز می‌شود.⁩
