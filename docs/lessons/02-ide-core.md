# ⁧درس ۲: ساخت Workspace، فایل، تب و ذخیرهٔ محلی⁩

## ⁧هدف و پیش‌نیاز⁩

⁧در این درس مسیر یک عملیات، مثل تغییرنام پوشه، را از کلیک تا داده، Monaco، Preview و ذخیره دنبال می‌کنید. قبل از شروع، props، `useState`، setter تابعی، `map`، `filter`، `Set`، union در TypeScript و Promise را مرور کنید. یک درخت شامل پوشه‌ای با دو فایل روی کاغذ بکشید و برای هر مورد شناسه بنویسید.⁩

## ⁧مدل داده و عملیات خالص⁩

- ⁧`src/features/project/tree.ts`. نوع `Entry` از union فایل و پوشه می‌آید. `FileEntry` متن دارد و `FolderEntry` ندارد. هر دو شناسه، نام و شناسهٔ والد دارند و والد `null` یعنی ریشه. `entryPath(entries, entry)` مسیر رشته‌ای می‌سازد و `filePaths(entries)` آرایه‌ای از فایل‌ها و مسیرها می‌دهد.⁩
- ⁧`addEntry(entries, id, parentId, name, kind)` یک آرایهٔ جدید می‌دهد. `renameEntry(entries, id, name)` و `moveEntry(entries, id, parentId)` شناسه را حفظ می‌کنند و یک فیلد را تغییر می‌دهند. تابع داخلی `validName` نام و والد را اعتبارسنجی می‌کند. نام همسان با تفاوت بزرگی و کوچکی حروف در یک پوشه رد می‌شود. `branchIds(entries, id)` همهٔ شناسه‌های زیرشاخه را می‌دهد. `deleteEntry(entries, id)` آن شناسه‌ها را حذف می‌کند.⁩
- ⁧`src/features/project/project.ts`. نوع `Project` نام، فایل‌ها، شناسهٔ تب‌ها، فایل فعال و پوشه‌های باز را دارد. `WorkspaceData` چند Project و شناسهٔ پروژهٔ فعال را نگه می‌دارد. `createProject(name)` از قالب نمونه، دادهٔ آماده می‌سازد. `editFile(project, id, content)` متن جدید را در snapshot پروژه قرار می‌دهد. `openFile` و `closeTab` پروژهٔ به‌روزشده را برمی‌گردانند. `withEntries(project, entries)` تب‌ها، فایل فعال و پوشه‌های باز را با درخت جدید هماهنگ می‌کند.⁩

```ts
const tabs = project.tabs.filter((id) => files.has(id))
const activeFileId = project.activeFileId && tabs.includes(project.activeFileId)
  ? project.activeFileId : tabs.at(-1) ?? null
```

⁧خط اول فقط شناسهٔ فایل‌های موجود را نگه می‌دارد. شرط خط دوم بررسی می‌کند که تب فعال هنوز موجود باشد. خط سوم آخرین تب باقی‌مانده یا `null` را انتخاب می‌کند. برای بستن عادی تب، `closeTab` بر اساس جای تب بسته‌شده همسایه را انتخاب می‌کند.⁩

## ⁧رابط و مسیر انتقال داده⁩

1. ⁧`src/app/App.tsx`، داده‌ها را از `useWorkspace` می‌گیرد و پروژهٔ فعال را با `key` به `Workspace` می‌دهد. انتخاب پروژهٔ دیگر باعث unmount فضای کار قبلی و ساخت فضای کار جدید می‌شود. `onUpdate(projectId, change)` با setter تابعی تغییر را روی snapshot تازه اعمال می‌کند.⁩
2. ⁧`Explorer.tsx` با `renderBranch(parentId)` بچه‌های هر پوشه را به ترتیب پوشه و فایل نمایش می‌دهد. کلیک روی پوشه، باز بودن آن را تغییر می‌دهد و کلیک روی فایل، شناسه را باز می‌کند. `FileMark(name)` نشان پسوند است. نتیجهٔ جست‌وجو از مسیر و متن فایل‌ها محاسبه می‌شود و نخستین خط منطبق هر فایل را نشان می‌دهد. انتخاب نتیجه تب همان شناسه را باز می‌کند.⁩
3. ⁧`WorkspaceDialog.tsx` از prop عملیات می‌فهمد ورودی نام، مقصد یا تأیید حذف لازم است. `onSubmit(name, parentId)` داده را به Workspace می‌دهد. خطای اعتبارسنجی در dialog باقی می‌ماند. برای حرکت دادن پوشه، مقصدهای زیرشاخه در فهرست نیستند و تابع خالص نیز مانع چرخه می‌شود.⁩
4. ⁧`TabBar.tsx` از Project و فهرست مسیرها، عنوان تب و دکمهٔ بستن را نمایش می‌دهد. ورودی callbackها شناسه است و تغییرنام تب فعال را از بین نمی‌برد. `EditorPane.tsx` مدل‌ها را بر اساس شناسه نگه می‌دارد و مدل فعال را در Monaco می‌گذارد. قبل از تعویض تب، موقعیت و scroll با `saveViewState` گرفته می‌شود. هنگام تغییر مسیر، URI تازه لازم است و `dispose` مدل قدیمی را آزاد می‌کند. Undo در همان URI و همان جلسه می‌ماند.⁩
5. ⁧`ResizeHandle.tsx` مقدار درصد و callback را می‌گیرد. تغییر فاصلهٔ افقی اعمال‌شده با اشاره‌گر را به اختلاف درصد تبدیل می‌کند. کلیدهای جهت سه واحد تغییر می‌دهند و `Home` و `End` به مرز می‌روند. `styles.css` درصد را به grid می‌دهد و روی عرض باریک، Preview را زیر editor می‌برد.⁩
6. ⁧`PreviewPane.tsx` فایل‌ها را با مسیر فعلی دریافت می‌کند. بعد از انتقال یا تغییرنام یک فایل، Sandpack snapshot با مسیر جدید دریافت می‌کند. اگر فایل واردکننده هنوز به مسیر قبلی اشاره کند، همان خطا نشان داده می‌شود. در تمرین، متن import را خودتان اصلاح کنید.⁩

## ⁧IndexedDB و رفتار هنگام تعارض⁩

⁧`src/lib/workspaceDb.ts` کار با درخواست و تراکنش مرورگر را جدا می‌کند. `openWorkspaceDb()` یک اتصال می‌دهد. `readWorkspace(db)` یک snapshot همراه revision یا `null` می‌دهد. `restoreWorkspace(raw)` نسخه، نوع داده، نام تکراری و زنجیرهٔ والدها را بررسی می‌کند. `saveWorkspace(db, data, expected)` در یک تراکنش هم revision را می‌خواند و هم در صورت تطابق ذخیره می‌کند. Promise پس از کامل شدن تراکنش، revision تازه را می‌دهد.⁩

```ts
if ((request.result?.revision ?? null) !== expected) {
  conflict = true
  transaction.abort()
  return
}
records.put({ version: 1, revision, workspace }, 'current')
```

⁧شرط اول نسخهٔ رکورد فعلی را با نسخه‌ای که این تب آخرین بار خوانده یا نوشته مقایسه می‌کند. برخورد، تراکنش را لغو می‌کند. خط آخر داده و revision جدید را در یک رکورد می‌نویسد. `useWorkspace.ts` نوشتن‌های خود تب را در صف Promise می‌گذارد و خطای ذخیره را در UI نشان می‌دهد. برای آزمایش دستی، تغییر یک تب را ذخیره کنید و سپس در تب قدیمی همان origin تغییری بدهید.⁩

## ⁧ترتیب پیاده‌سازی دوباره و تست⁩

1. ⁧درخت داده و مسیر را ابتدا با سه ورودی ساده بسازید. نام تکراری، پوشهٔ والد نامعتبر و انتقال پوشه به خودش را با unit test پوشش دهید.⁩
2. ⁧Explorer را به state وصل کنید و شناسه‌های تب و فایل فعال را اضافه کنید. معیار قبولی، تغییرنام فایل با تب باز و حذف پوشه همراه حذف تب فرزند است.⁩
3. ⁧مدل Monaco را به شناسه وصل کنید. قبل از نوشتن IndexedDB، تغییر سریع متن و جابه‌جایی تب را بررسی کنید. سپس snapshot را به Preview بدهید و مسیر یک import خراب را در پیام خطا دنبال کنید.⁩
4. ⁧خواندن و نوشتن IndexedDB و سپس بازیابی پس از reload را پیاده کنید. ابتدا خواندن و بعد نوشتن اولیه را فعال کنید تا پروژهٔ پیش‌فرض، دادهٔ قبلی را بازنویسی نکند. یک آزمون با دو تب اضافه کنید.⁩

```sh
npm run test
npm run test:e2e -- workspace.spec.ts
```

⁧اگر تب باز ولی متن اشتباه است، شناسهٔ فعال و URI مدل را با مسیر جدید مقایسه کنید. اگر ذخیره شکست خورد، پیام وضعیت را قبل از reload بخوانید. در تعارض، متن مهم را از تب قدیمی کپی کنید و بعد نسخهٔ ذخیره‌شده را باز کنید. اگر تغییر فایل در Preview دیده نشد، اول نوع خطا و بعد مسیر import را بررسی کنید.⁩

## ⁧تمرین و سؤال دفاع⁩

- ⁧از روی تست `project.test.ts` یک پوشه و یک زیرفولدر بسازید. بررسی کنید که فقط مسیر با انتقال تغییر می‌کند. یک تست برای پاک‌شدن تب‌های فرزند اضافه کنید.⁩
- ⁧جست‌وجو را طوری تغییر دهید که بتوان با انتخاب نتیجه به خط اول منطبق رفت. ابتدا تفاوت شمارهٔ index و شمارهٔ خط Monaco را توضیح دهید و بعد در Playwright موقعیت cursor را بررسی کنید.⁩
- ⁧استاد ممکن است بپرسد اگر مسیر را شناسهٔ تب قرار می‌دادید، بعد از rename و move چه چیزهایی باید تغییر می‌کرد؟ این پیاده‌سازی کجا هنوز به مسیر وابسته است؟⁩
- ⁧استاد ممکن است تفاوت undo در حالت بستن تب و تغییر مسیر را بپرسد. یک سناریوی قابل تکرار برای هر دو توضیح دهید.⁩
- ⁧استاد ممکن است بپرسد اگر دو تب با یک revision شروع کنند، کدام تراکنش موفق است و پیام شکست کجا نمایش داده می‌شود؟ به درخواست خواندن داخل تراکنش اشاره کنید.⁩
